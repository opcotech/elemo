# Permission-aware search

## Abstract

Elemo exposes permission-aware global search as a Meilisearch-backed
projection. Neo4j and the existing ReBAC permission layer remain the source of
truth for what a caller may read. Meilisearch stores searchable text, resource
type, and **scope ancestry** — never per-user ACL lists. Hits are filtered by
the caller's grant scopes and confirmed with `Has` before they are returned.

This is a sibling backing store, not a Redis-style cache-aside decorator of
Neo4j `Get`/`List`.

## Decision

### Layering

```text
Neo4j / PermissionService  →  what the user may access
Elemo SearchService        →  authz filter + index sync + post-check
Meilisearch                →  text search, ranking, attribute filters
```

Domain services write through to the index after persist (create, update,
move, delete). Indexing errors are logged and do not fail Neo4j CRUD. Drift is
repaired with `elemo search reindex`.

### Indexed document

A single shared index holds Organizations, Namespaces, Projects, Issues, and
Documents. The Meilisearch primary key is `ResourceType_xid` because Meilisearch
rejects `:` in document identifiers. Filter fields (`scope_ids`,
`organization_id`, and so on) still store the typed `ResourceType:xid` form.
Client filters are parsed as Elemo IDs and AND-ed onto the authz filter. Raw
Meilisearch filter strings are never accepted.

### Grant-scope filter

`ListVisible` expands to every visible resource of a type and is too large for
a Meilisearch `IN` clause. Search uses `ListGrantScopes`: the same principal
walk as `Has` (user, team, organization — including foreign-org collaboration)
returning distinct grant **scopes** for each read action. Per-type filter
branches are:

```text
(type = "Issue" AND scope_ids IN [scopes with issue.read])
OR (type = "Project" AND scope_ids IN [scopes with project.read])
OR ...
```

If a type has no grant scopes, that branch is omitted. If every branch is
empty, the service returns an empty page without querying Meilisearch.

Each hit is then post-validated with `Has`. Pagination uses an opaque offset
token and omits `total_count` so unauthorized hits cannot leak through counts.

### Why not Redis decoration

Redis wraps `Get`/`List` as cache-aside. Search is a write-through projection
plus a query path: it is not a drop-in for any Neo4j repository method, does
not store full DTOs, and must not be treated as an authorization cache.

## Consequences

- Existing resources are invisible to search until they are indexed (create
  hooks going forward, `elemo search reindex` for backfill).
- Soft-deleted or revoked resources may remain in the index until the next
  write or reindex; `Has` post-filter is the safety net.
- Full document bodies, facets, autocomplete, and frontend/command-palette
  wiring are out of scope.
