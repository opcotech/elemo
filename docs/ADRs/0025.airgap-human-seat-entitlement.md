# AirGap Human-Seat Entitlement

| author       | created at | updated at | status   |
|:-------------|:-----------|------------|:---------|
| @gabor-boros | 2026-09-07 | 2026-09-08 | accepted |

## Abstract

Elemo ships two compile-time artifacts. The default self-hosted binary is
unrestricted: it reads no license, enforces no human-seat ceiling, and
exposes every ordinary product feature. The commercial AirGap artifact
enforces a vendor-signed, offline, active-human seat entitlement. Cloud
storage and retention quotas are a separate billing concern and are not
modeled here.

This decision supersedes [ADR 0016](0016.generating-and-validating-licenses.md).
The previous mandatory `lk` license mixed feature flags, artificial quotas,
and startup-fatal expiry. That trust set is retired because the historical
signing private key was published.

## Decision

### Deployment mode

Mode is selected at compile time (`//go:build airgap` versus the default
`!airgap` files in `internal/deployment`). Configuration and environment
variables cannot turn a self-hosted binary into an AirGap binary. CI
compiles both. The published Docker image remains the self-hosted artifact.

### Trust and format

AirGap licenses are a versioned JSON envelope (`elemo.airgap.license.v1`)
signed with standard-library Ed25519. The signed message is domain-separated
and includes the format version, key ID, and exact payload bytes. The
verifier does not reserialize the payload. Decoding is strict: bounded file
size, unknown-field rejection, required field order, and signature
verification before payload use.

The production AirGap artifact embeds a key-ID-to-public-key trust set. No
public-key config or self-signed escape hatch exists. Test keys are injected
only in tests and are not compiled into the production trust set. Signing
private keys never enter the repository.

Payload fields: license ID, customer, logical installation UUID, active-human
seat count, issued-at, not-before, and expiration. There are no ordinary
feature flags, support flags, or resource quotas.

### Installation identity

A logical installation UUID is stored on the singleton Neo4j
`Installation` node, separate from its stable nil resource ID. It is
generated once, preserved in backups, logged at AirGap startup, and
returned only on the administrator entitlements endpoint. Node replacement
and Kubernetes rescheduling do not change it. Restoring the database
restores it. Losing the database identity requires a vendor reissue.

### Lifecycle

Evaluated states are `valid`, `grace`, `expired`, `not_yet_valid`,
`invalid`, and `missing`. Time is UTC with an injected clock in tests and a
five-minute not-before skew. After `expires_at`, a fixed 30-day grace
window continues to allow seat-limited activations and ordinary domain
writes. After grace, and in every state that cannot establish a current
or in-grace entitlement (`expired`, `missing`, `invalid`,
`not_yet_valid`), the instance is fail-closed: new human activations are
denied and user-initiated creates, updates, and deletes are rejected.
Reads, login, password reset, user deactivation, license recovery, export,
backup, and background search indexing or custom-field reconciliation
remain available.

A missing or invalid license does not terminate the AirGap server. It
puts the instance into restricted activation and read-only mode. License
replacement is a file mount update plus rolling restart. A replacement
with a lower seat count never deactivates existing users; activation resumes
after usage falls below the limit.

Official bundle and release eligibility ends at license expiration and is
enforced by vendor distribution, not by disabling an installed runtime.
Grace does not extend access to newer official bundles.

Clock rollback is an offline operational trust assumption. The runtime does
not add hardware or network time sources.

### Seats

Only `UserStatusActive` human users count. Pending invitations, inactive
users, and deleted users do not. Invitation acceptance and every
non-active-to-active transition consume a seat. Active-to-active updates
do not. OAuth and API clients are delegated identities and do not count.
Finite-seat activation is atomic in Neo4j by serializing through the
Installation node and checking `active_count < limit` in the same
transaction.

Self-hosted returns an unrestricted activation and mutation policy. AirGap
returns a finite seat limit and allows writes while valid or in grace, and
denies both activation and domain mutations otherwise.

Activation and mutation product rules live on the AirGap policy, not on the
license lifecycle enum. Production AirGap policy construction requires a non-nil
active-human counter so status cannot report a silent zero.

### Mutation and activation authorization

Every command-capable service takes an explicit mutation policy. A nil policy
fails closed. Self-hosted composition passes `Unrestricted()` deliberately.
The write gate is operation-scoped: the first successful authorization stamps
the request context so nested service calls reuse that decision instead of
re-evaluating a clock-based policy after an earlier write.

User-status exceptions are narrow. Password reset and explicit inactive or
deleted transitions remain available while read-only. Pending and active
transitions, profile updates, and `Delete(force=true)` do not.

Seat activation cannot be omitted. Repository activation authorization is a
validated value with finite and unrestricted constructors. A nil authorization
means no activation was requested, never unlimited. Active create, `Activate`,
and invitation acceptance share that value.

Invitation acceptance applies activation, invitation deletion, membership,
and an optional role grant in one Neo4j transaction. Cache invalidation after
a committed activation or acceptance is best-effort.

### Operator surface

`GET /v1/system/entitlements` is administrator-only. It reports deployment
mode, installation ID, lifecycle dates, active and licensed seats, and
grace end when applicable. License validity is not part of system health.
The settings UI shows a warning for AirGap grace, expired, invalid,
missing, and not-yet-valid states. Blocked writes return HTTP 409 with
`code: entitlement_read_only`. Normal self-hosted renders no licensing
UI. AirGap sends a daily email to `airgap.billing_email` while a verified
license is within seven days of expiration, in grace, or expired. There is
no license upload API.

## Consequences

* Self-hosted customers delete any former `license.file` configuration.
  AirGap customers require a newly issued vendor-signed license bound to
  their installation UUID. Every old `lk` license is invalid.
* Custom fields, plugins, multiple assignees, and other ordinary
  collaboration features are authorization- and configuration-gated only.
* `LICENSE-COMMERCIAL` still mentions order-form feature gates and quotas.
  Changing those legal terms requires a separate legal review.
* Vendor tooling in `tools/key-generator`, `tools/license-generator`, and
  `tools/license-validator` issues and inspects the Ed25519 envelope.
